# Отчет по аудиту безопасности (Hardening) приложения Hostel

## 1. Объект аудита
Приложение для бронирования отелей «Hostel» (сборка release/debug).
**Область проверки:** Безопасность передачи данных (HTTPS), проверка подлинности сертификатов, контроль доступа к данным (SharedPreferences) и сборка.

## 2. Найденные уязвимости и исправления

### FIND-001: Передача данных по незащищенному протоколу (HTTP)
*   **Уязвимость (MASVS-NETWORK-1):** В приложении не был запрещен Cleartext (незашифрованный) HTTP-трафик. Если бы сервер API работал по HTTP, данные пользователя (пароли, брони) могли быть перехвачены.
*   **Степень риска:** Высокая (High, CVSS 7.5).
*   **Как исправлено (Hardening):**
    1. В `AndroidManifest.xml` добавлен атрибут `android:usesCleartextTraffic="false"`.
    2. Создан файл `res/xml/network_security_config.xml`, в котором прописан запрет `cleartextTrafficPermitted="false"` для всех доменов.
    3. В `AndroidManifest.xml` добавлена ссылка на конфиг: `android:networkSecurityConfig="@xml/network_security_config"`.
*   **Результат:** Приложение теперь физически не может отправить запрос по `http://`, только по защищенному `https://`.

### FIND-002: Отсутствие проверки подлинности сертификата (SSL Pinning)
*   **Уязвимость (MASVS-NETWORK-2):** Приложение доверяло любым системным сертификатам. Это означает, что злоумышленник мог настроить прокси (mitmproxy) и перехватить HTTPS-трафик, если на телефоне установлен его корневой сертификат.
*   **Степень риска:** Средняя (Medium, CVSS 6.0).
*   **Как исправлено:** В коде (файл `PostsApi.kt` или `RetrofitClient.kt`) внедрен механизм **OkHttp CertificatePinner**. Мы «привязали» (pin) публичный ключ (SPKI) нашего сервера. Теперь, если сертификат подменят (даже легальным CA), соединение будет разорвано.
*   **Результат:** MITM-атака через прокси невозможна без взлома самого приложения.

### FIND-003: Незащищенное хранение сессионных данных
*   **Уязвимость (MASVS-STORAGE-1):** Данные пользователя (пароли, роли, брони) сохранялись в обычный `SharedPreferences` (открытый XML-файл). На рутованном устройстве злоумышленник мог легко прочитать пароль.
*   **Степень риска:** Высокая (High, CVSS 7.0).
*   **Как исправлено:** Использована библиотека `androidx.security:security-crypto`. Код в `AuthManager.kt` переписан на **`EncryptedSharedPreferences`**. Ключ шифрования генерируется в `AndroidKeyStore` (аппаратный уровень TEE).
*   **Результат:** Файл `auth_prefs.xml` теперь содержит нечитаемый шифртекст.

### FIND-004: Отсутствие обфускации кода (Reverse Engineering)
*   **Уязвимость (MASVS-RESILIENCE-1):** В `app/build.gradle.kts` был отключен `minifyEnabled` (R8). Любой человек мог открыть APK в JADX и прочитать логику работы, найти названия функций и структуру базы данных.
*   **Степень риска:** Средняя (Medium, CVSS 5.0).
*   **Как исправлено:** В `build.gradle.kts` для `release` сборки включены:
    ```kotlin
    isMinifyEnabled = true
    isShrinkResources = true
    isDebuggable = false
